# samples 폴더 사용법

> **실제 부처 파일이 없을 때**: `npm run samples`를 실행하면 `samples/예시/`에 사진 속 문서 양식을 흉내 낸 **가짜 예시 한글 파일 19개**가 만들어져요. 부처와 숫자는 엑셀 예시표를 따르고(조달청 신규 80 등), 업체·제품 이름은 모두 지어낸 거예요. 앱에 올리면 엑셀 예시표와 같은 표(계 89·33·48·4·3)가 나와야 해요. `npm run check -- "samples\예시"`로 내 컴퓨터에서 읽기만 확인할 수도 있어요.
>
> **40개짜리**: `npm run samples:40`을 실행하면 `samples/예시40/`에 엑셀 예시표의 부처 10곳 × 다섯 구분 50칸 중 10칸(규격추가 6곳, 신규지정 2곳, 지정취소 2곳)을 뺀 **40개**(합계 약 11MB)가 만들어져요. 문서를 내지 않은 칸은 표에서 **빈칸**이어야 해요. 앱에 한꺼번에 올리면 계 69·45·58·43·18이 나와야 해요.

> **지난 분기 표 예시**: `npx tsx scripts/make-previous-report.ts`를 실행하면 `samples/지난분기_기준표.xlsx`가 만들어져요. 엑셀 예시표 사진(계 89·33·48·4·3)을 그대로 옮긴 파일이라, "지난 분기 표 선택"에 올리면 비교표를 시험할 수 있어요. 예시 40개와 함께 올리면 계가 69(-20)·45(+12)·58(+10)·43(+39)·18(+15)로 나와야 해요.

부처가 보낸 **실제 한글 파일**과, 그 파일에서 **손으로 센 정답표**를 넣어 두는 곳이에요.
앱이 숫자를 정확히 읽는지 확인하는 기준(정답)이 됩니다.

> **중요**: 이 폴더의 실제 파일은 내부용 자료라서 GitHub에 올라가지 않아요(`.gitignore`로 제외).
> 이 안내문(`README.md`)과 가짜 숫자로 만든 `answers.example.json`만 올라가요.

## 1. 샘플 파일 넣기

구분별로 **하나씩**, 가능하면 부처가 다른 파일을 이 폴더에 넣어 주세요.

| 구분 | 꼭 필요한가 | 메모 |
|------|:-----------:|------|
| 신규지정 | ✅ | 사진·기대효과가 있는 양식 |
| 1차 연장 | ✅ | |
| 2차 연장 | ✅ | 접수 건수와 인정(연장된) 건수가 **다른** 파일이면 더 좋아요 |
| 지정취소 | 있으면 | 없으면 비워 두세요 (그 구분은 "파일 없음"으로 시험해요) |
| 규격추가 | 있으면 | 없으면 비워 두세요 |

더하면 좋은 파일 (있다면):
- 건수가 `-`(없음)로 적힌 파일
- 같은 문서를 `.hwp`(구형)로도 저장한 파일
- 부처명이 길거나 특이한 파일

파일 이름은 **그대로** 두세요. (이름을 바꾸면 정답표와 맞지 않아요.)

## 2. 정답표 만들기

1. `answers.example.json`을 복사해서 이름을 **`answers.json`**으로 바꿉니다.
2. 파일마다 한 줄씩, **사람이 직접 세어서** 적습니다.
   - `fileName`: 샘플 파일 이름 (확장자 포함)
   - `ministry`: 기준표에 쓸 부처 줄임말 (예: 해수부)
   - `category`: `신규지정`, `1차연장`, `2차연장`, `지정취소`, `규격추가` 중 하나
   - `count`: 기준표에 들어가야 할 숫자. 건수가 없어서 **빈칸**이어야 하면 `null`, 읽기 어려워 **"확인 필요"**여야 하면 `"확인필요"`
3. 맨 아래 `expectedTotals`에는 구분별로 "계" 행에 들어갈 숫자를 적습니다. (샘플 파일들만 합쳤을 때의 값)

2차 연장은 접수가 아니라 **연장된(인정된) 건수**를 적어야 해요.

## 3. 주의

- 정답은 앱이 읽은 값을 복사하지 말고 **문서를 보고 직접** 세어 적어 주세요. 앱의 답과 정답이 같은 값에서 나오면 확인이 되지 않아요.
- 숫자가 확실하지 않은 칸은 비워 두지 말고, 어느 파일의 어디가 헷갈리는지 알려 주세요.
