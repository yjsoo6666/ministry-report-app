# 부처별 기준표 자동 취합 앱

부처들이 보낸 한글(hwpx) 파일을 올리면 부처별·구분별 건수를 읽어 **엑셀 기준표**를 만들어 주는 앱이에요.
지난 차수 기준표를 함께 올리면 증감이 들어간 **비교표**도 만들어요.

- 한글 파일은 **이 컴퓨터의 브라우저 안에서만** 읽어요. 서버나 외부 서비스로 보내지 않고, 저장도 하지 않아요.
- 기획과 규칙은 [PRD.md](PRD.md), 만들 순서는 [PLAN.md](PLAN.md), 구조는 [DESIGN.md](DESIGN.md)에 있어요.
- 작업 규칙은 [CLAUDE.md](CLAUDE.md)에 있어요.

## 실행하기

```bash
npm install     # 처음 한 번만
npm run dev     # 개발 서버 → http://localhost:3000
```

| 명령 | 하는 일 |
|------|---------|
| `npm run dev` | 개발 서버를 켜요 |
| `npm run build` | 배포용으로 빌드해서 오류를 확인해요 |
| `npm run lint` | 코드 검사 |
| `npm test` | 숫자 계산·파일 읽기가 맞는지 자동 시험 |

## 쓰는 방법

파일은 **여러 개를 한 번에** 올릴 수 있어요. 파일 100개(합계 약 80MB)를 한 번에 올려 봤을 때 1초 안에 읽혔고, 사진 데이터가 든 문서 40개(약 11MB)도 0.5초 안팎에 읽혀서 숫자가 정답과 같았어요. (사진을 흉내 낸 시험 파일 기준이에요.) 파일 하나는 20MB까지, 한 번에 4개씩 읽어요.
예시 파일을 만들어 보려면 `npm run samples`(19개), `npm run samples:40`(40개, 빈칸 있음)을 쓰세요.

화면은 3단계예요.

1. **파일 올리기**: 부처가 보낸 한글 파일(`.hwpx`)을 올려요. (선택) "이번 조달심 차수"에 4처럼 숫자를 적고 3차 기준표 엑셀을 올리면 비교표도 만들어요.
2. **확인하기**: 읽지 못한 칸이나 확인할 파일만 카드로 보여요. 문서를 보고 숫자를 직접 적거나, 빈칸·제외로 정리해요. 아래 표에서 칸을 눌러 숫자를 고칠 수도 있고, 고치면 "계"가 다시 계산돼요.
3. **완성**: 구분별 합계와 (3차 표가 있으면) 증감을 보고 **엑셀 다운로드**를 눌러요. 한 파일에 시트 1 "기준표", 시트 2 "3차 대비 비교표"가 들어가요. 지난 표와 부처 이름이 다르면(이름이 바뀐 부처) "같은 부처인가요?"라고 물어봐요.

## 폴더 안내

| 위치 | 내용 |
|------|------|
| `app/` | 화면 (`page.tsx`, `_components/`) |
| `lib/reader/` | 한글 파일에서 글자 꺼내기 |
| `lib/parse/` | 부처명·구분·건수 읽기, 부처 줄임말 |
| `lib/table/` | 표 합치기, "계" 계산, 칸 수정, 비교표 계산 |
| `lib/excel/` | 엑셀 만들기·읽기 |
| `tests/` | 자동 시험 |
| `samples/` | 샘플 한글 파일과 정답표 (내부용이라 GitHub에 올라가지 않아요) |

## 실제 부처 파일을 AI에게 보여주지 않고 확인하기

내부용 한글 파일을 AI(코딩 도우미)에게 읽히면 그 내용이 AI 서비스로 전송돼요. 대신 **내 컴퓨터에서만** 도는 확인 도구로 "앱이 이 파일을 맞게 읽는지" 직접 볼 수 있어요. 파일을 어디로도 보내지 않고, 아무것도 저장·수정하지 않아요.

```bash
npm run check -- "C:\내폴더\부처파일들"          # 폴더를 주면 안의 .hwpx/.hwp를 모두 읽어요
npm run check -- "C:\내폴더\해수부_신규.hwpx"    # 파일 하나만
npm run check -- "C:\내폴더\해수부_신규.hwpx" --lines   # 문서에서 꺼낸 글자 줄도 같이 보여줘요
```

- 파일마다 "부처 · 구분 · 건수"가 나오고, 마지막에 앱이 만들 표가 글자로 나와요. 원본 한글 파일을 열어 숫자와 비교해 보세요.
- 숫자가 틀리거나 못 읽으면 `--lines`로 나온 줄 중 **건수가 적힌 줄의 모양만** 알려 주세요. (업체명, 사업 내용은 빼고 글자 모양만 알려 주면 규칙을 고칠 수 있어요.)

## 인터넷에 공개하기 전에 (보안)

- 이 앱은 내부용 자료를 다루므로 **공개 주소에 접근 제한을 거는 것**을 권해요. Vercel 프로젝트 설정의 *Deployment Protection*(Vercel 로그인 또는 비밀번호)을 켜 주세요. 코드로는 대신 못 해요.
- Vercel CLI로 배포할 때는 `.gitignore`가 적용되지 않아서 `.vercelignore`로 `.env`, `samples/`, `trash-can/`, `.bkit/`를 막아 뒀어요. 이 파일을 지우지 마세요.
- 한 번이라도 `.env`가 들어 있는 채로 배포했다면 그 안의 토큰 4개를 새로 발급해 교체하세요.
- 시험용 가짜 파일은 `samples/`에서 만들어 쓰세요(`npm run samples:40`). 화면에는 예시 데이터 버튼이 없어요.
- `npm audit`에 뜨는 취약점은 개발용 도구(린트) 쪽이거나 이 앱이 쓰지 않는 기능이라 앱 사용자에게는 위험이 없어요. `npm audit fix --force`는 큰 버전 변경을 일으킬 수 있으니 실행하지 마세요.

## 아직 안 된 것

- 구형 `.hwp` 파일 읽기: 지금은 한글에서 `.hwpx`로 다시 저장해서 올려야 해요.
- 지정취소 문서 읽기: 문서 양식을 확인한 뒤에 만들 수 있어요.
- 실제 부처 파일로 숫자가 100% 맞는지 확인하는 일
